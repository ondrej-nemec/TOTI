Get started

Preparations

The tutorial expected you have created Java Gradle project with dependency on TOTI Core. TOTI use Log4j2 so you will probably need dependency on some implementation of it.

Initialize server

We start with creating TotiServerFactory. This class helps with configuring a server. You can create it with given path to configuration file or with properties or without parameters to use default configuration or to set it manualy in code. For now, we let everything default.
From TotiServerFactroy we create TotiServer. If we call start, our program will be listening on ports 80 and 443.
Our class can look like this: 

public class GetStartedMain {
	
	private final Logger logger;
	private final TotiServer server;

	public GetStartedMain() {
		this.logger = LogManager.getLogger("toti-get-started");
		TotiServerFactory serverFactory = new TotiServerFactory();
		// there can be server configuration
		this.server = serverFactory.create(logger);
	}

	public void start() {
		try {
			server.start();
		} catch (Exception e) {
			logger.fatal("GetStarted:start fails", e);
		}
	}

	public void stop() {
		try {
			server.stop();
		} catch (Exception e) {
			logger.fatal("GetStarted:stp fails", e);
		}
	}

	public static void main(String[] args) {
		// no need to call stop - this is just demo stopped from IDE
		new GetStartedMain().start();
	}

}
Our program is binding ports, but all requests return 404.

Applications

Application from TOTI perspective is one application running on web server (TotiServer). One server can has more applications. You can add or remove Application from server before or after server start. Here we will add our application right after server create. 

server.addApplication("getStarted", (env, applicationFactory)->{
	// there can be application configuration
	applicationFactory.setDevModeFunc(ip->true); // dev mode
	return applicationFactory.create(Arrays.asList(), logger);
}, null, null);
First argument is unique name for you application. Second is callback. Callback provide env (part of server env relatet to your application) and application factory (allows configure application). A result is new Application created from applicationFactory. Last two arguments are used if you have more applications. Can stay null here.
create method requires list of Modules and logger. List can be empty.
Also, we set the application to develop mode. In develop mode, TOTI displays more information in browser.
Now, if you restart your program and make request you get... 404. But now, you can see more details.
Just verify TOTI is working, try use /toti as URI. You should see TOTI welcome page.

Handling requests

Module

To start receiving and handling requests, we first need to create module. Module is logical part of application.
In this case we will create CoreModule. Every module must implement Module interface. 

public class CoreModule implements Module {

	private final Logger logger;

	public CoreModule(Logger logger) {
		this.logger = logger;
	}

	@Override
	public String getName() {
		return "core";
	}

	@Override
	public List init(Env env, Register register, Link link, Router router) {
		return Arrays.asList();
	}

}
And add module to application: 

	return applicationFactory.create(Arrays.asList(
		new CoreModule(logger)
	), logger);
Every module has to have not null name. Name can be empty string and must be unique in application.
In init method you initialize classes the module use.
  • env same as application has
  • register allows register controllers and share instances between modules
  • link to create link inside your application
  • router to modify routing
Method returns list of Tasks (will be explained later).

Controller

Then we need some controller. Every TOTI controller must be annotated with @Controller. This annotation requires string parameter - name. The name must be not null. 

import toti.core.annotations.Controller;

@Controller("welcome")
public class WelcomeController {

}
Do not forgot register controler in module: 

	register.addController(WelcomeController.class, ()->new WelcomeController());
Actual request handling is done inside controller methods annotated as @Action. You can specify path and allowed HTTP methods in the annotation.
Action has to return ResponseAction. ResponseAction is callback. It provides Request (holds information about request: parameters, headers) and Identity (holds information about user). Return type is Response. 

	@Action(path="hello")
	public ResponseAction hello() {
		return (request, identity)->{
			return Response.OK()
			.addHeader("Content-type", "text/html")
			.getText(">h1<Hello World!>/h1<");
		};
	}
To check everyting works, visit: /core/welcome/hello.
We can make it more interesting using query parameters: 

	@Action(path="hello")
	public ResponseAction hello() {
		return (request, identity)->{
			String name = request.getQueryParam("name").getString();
			if (name == null) {
				name = "World";
			}
			return Response.OK()
			.addHeader("Content-type", "text/html")
			.getText(">h1<Hello " + name + "!>/h1<");
		};
	}
We can change message using name parameter: /core/welcome/hello?name=TOTI.
If we need have some parameter(s) in path, we define them in action definition. 

	@Action(path="guess")
	public ResponseAction guess(Integer from, Integer to) {
		return (request, identity)->{
			return Response.OK()
			.addHeader("Content-type", "text/html")
			.getText(">div<Guess number between " + from + " to " + to + ">/div<");
		};
	}
The page is available at fe. /core/welcome/guess/1/100
Combination of controller name, action path and action path parameter count must be unique inside module.

Tasks

Task is something that needs to start and stop with application. Task interface define start and stop method. The methods are called during application start/stop. The methods are not called in separated threads.
Lets's make task that increment some value by 1 every 1 second. First we need some class to hold values: 

public class Counter {

	private int count;

	public int getCount() {
		return count;
	}

	public void increase() {
		count = count + 1;
		if (count == Integer.MAX_VALUE) {
			count = 0;
		}
	}

}
Now we can create task: 

import java.util.concurrent.Executors;
import java.util.concurrent.Future;
import java.util.concurrent.ScheduledExecutorService;
import java.util.concurrent.TimeUnit;

import org.apache.logging.log4j.Logger;

import toti.core.application.Task;
import toti.examples.getStarted.core.services.Counter;

public class CounterTask implements Task {

	private final Counter counter;
	private final Logger logger;
	private final ScheduledExecutorService pool;
	private Future future;

	public CounterTask(Counter counter, Logger logger) {
		this.counter = counter;
		this.logger = logger;
		this.pool = Executors.newSingleThreadScheduledExecutor();
	}

	@Override
	public void start() throws Exception {
		future = pool.scheduleWithFixedDelay(()->{
			counter.increase();
		}, 0, 60, TimeUnit.SECONDS);
	}

	@Override
	public void stop() throws Exception {
		try {
			if (future != null) {
				future.cancel(true);
			}
			pool.shutdownNow();
		} catch (Exception e) {
			logger.error("Cannot stop pool", e);
		}
	}

}
Last, we create controller to show it in web.

}
Also, we need init everything in init method: 

	Counter counter = new Counter();
	register.addController(CounterController.class, ()->new CounterController(counter));
	return Arrays.asList(new CounterTask(counter, logger));
Our counter is available at /core/counter.
