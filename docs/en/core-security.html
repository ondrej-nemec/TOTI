Security

TOTI provides information about user who makes request. Also allows log in/out users, store server side data etc.

Identity

Instance of Identity is part of ResponseAction.

IP

getIP returns user IP.

Session Space

Session space are data related to unique user. It can hold data between requests. How data will be saved depends on SessionManager (see below).
getSessionSpace returns whole session space

Flash messages

Flash messages are string data. The messages are usualy displayed to user to notify him/her what happends on server.
addFlashMessage(severity, message) add new message to qeue.
getFlashMessages() returns list of all messages. WARNING! Qeue is automaticlly cleared.

Scope

Scope is holder for classes set by extensions. This allows to use request specific instances.
setScope(object) add object to scope
setScope(clazz, object) add object to scope
getScope(clazz) returns object of given class from scope or null
removeScope(clazz) remove object of given class from scope

User

Identity contains current logged user. In TOTI, user has no given interface or base class.
getUser returns Optional of Object
getUser(clazz) returns null if no user is present or try retype user to given class and return.
login(user) add user to identity
logout remove user from identity

User mode

Identity operates in three modes.
  • Anonymous no identification. Session space and flash messages are usualy NOT saved.
  • Not logged user there is no logged user, but there is some identification. Usualy means session space and flash messages can be used
  • Logged user there is logged user
Current user mode of Identity is available:
isAnonymous true if no identification is available, false otherwise
isUserPresent true if there is logged user, false otherwise

CSRF

TOTI comes with build in CSRF protection. Details depends on SessionManager, but Identity facilitates data.
isCsrfTokenVerified returns true if SessionManager mark request as CSRF verified
getCsrfToken returns token for current context or empty string if SessionManager not provide it

Session Manager

SessionManager is interface. How session is stored, how tokens are generated and sent to user depends on implementation.
SessionManager instance is set like this: 

applicationFactory.setSessionManager(sessionManager);
TOTI can work with now SessionManager set, but session space, flash messages and login cannot work without it.
SessionManager contains following methods:
onApplicationStart called once when application is starting
onApplicationStop called once when application is stopping
restoreSession(requestHeaders, queryParams, requestBody) called on start of every request. The point of this method is to find if request contains any information about session.
saveSession(responseHeaders, sessionId, sessionSpace, userMode, user) called on end of every request. The point of this method is to save data and set identifier to response headers.

DefaultSessionManager

Implement own SessionManager can be hard. So TOTI also comes with default implementation. It can be used or help with custom implementation.
Default implementation store session id in cookie. If request not contains session id or session is no longer valid, new session is created. This allows to send flash messages to not logged users. The sessions are stored in RAM. 

new DefaultSessionManager(applicationFactory.getBasePath(), 2 * 60L)
As first parameter, DefaultSessionManager needs application path. It is used in cookie path. The second parameter is max expiration time in seconds. If null, session never expired.
Important parameter is: 

DefaultSessionManager.CSRF_TOKEN_NAME
It is input name for CSRF.
